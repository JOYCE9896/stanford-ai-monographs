第八讲：推理系统与模型评估方法论

为什么"生成"比"训练"更受制于显存带宽，以及"模型好不好"这件事该怎么定义才有意义

主讲：Percy Liang（斯坦福大学计算机系教授）
对应真实课程材料：Lecture 10（Inference）、Lecture 12（Evaluation）讲稿

一、 训练和推理，是两种完全不同的计算模式

训练时，模型能一次性看到整段序列，前向传播里的矩阵乘法可以充分并行，这正是前几讲反复强调"要让 GPU 保持算力密集（compute-bound）"的场景。但推理时的生成阶段完全不同：模型每次只能生成一个 token，生成下一个必须先看到上一个，天然是串行的，没法像训练那样把整段序列铺开做批量矩阵乘法。

用上一讲学到的"算术强度"（arithmetic intensity）概念可以精确刻画这个差异：对一次矩阵乘法 $X(B\times D) \times W(D\times F)$，算术强度约等于 $B$（batch size）。讲义给出了 H100 的真实硬件参数，峰值算力约 989 TFLOPs/s，显存带宽约 3.35 TB/s，两者相除得到硬件本身的"临界算术强度"约为 295：只有当 $B > 295$ 时，计算才是"算力密集"的，否则就是"显存带宽密集"（memory-bound）。生成阶段一次只处理一个新 token（相当于 $B=1$ 的极端情况），算术强度只有 1，远低于 295。生成阶段几乎永远是显存带宽瓶颈，而不是算力瓶颈：GPU 的算力大量闲置，真正卡脖子的是数据搬得够不够快。这也是理解本讲后续所有推理优化技巧的核心出发点。

二、 KV Cache：用显存换计算，但显存本身又成了新瓶颈

如果每生成一个新 token 都要把历史上所有 token 重新过一遍完整的前向传播，生成 $T$ 个 token 的总计算量会是 $O(T^3)$ 级别（每步 $O(T^2)$，重复 $T$ 步）。这是完全无法接受的浪费，因为历史 token 的 Key、Value 向量在每一步生成时其实是不变的。解法是 KV Cache：把每个 token、每一层、每个注意力头算出来的 Key 和 Value 向量缓存在显存里，后续生成时直接复用，只需要为新 token 计算一次 Query 并和缓存好的 KV 做注意力，不必重算历史部分。推理因此被拆成两个阶段：Prefill（处理输入的 prompt，可以像训练一样并行、是算力密集的）和 Generation（一个个吐出新 token，串行、是显存带宽密集的）。

但 KV Cache 本身会占用大量显存，且随序列长度线性增长。于是后续一系列真实的模型架构创新，本质上都是在想办法压缩 KV Cache：

  • 分组查询注意力（GQA）：让多个 Query 头共享同一组 Key/Value 头（$N$ 个 Query 头分成 $K$ 组，每组共享一份 KV），把 KV Cache 缩小 $N/K$ 倍。讲义给出了一组基于 Llama 2 13B 的真实对比：把 $K$ 从 40（标准多头注意力）降到 8，batch size 64 时延迟略有下降但吞吐量明显提升（因为显存腾出来了，可以塞进更大的 batch）；把 batch size 进一步提到 256，吞吐量继续提升，GQA 论文的实验也确认了这个精度几乎不掉的结论。
  • 多头潜在注意力（MLA，DeepSeek v2 提出）：思路更激进，不直接缓存 Key/Value，而是缓存一个低维的"潜在"压缩向量，需要时再投影展开成完整的 K、V。讲义给出真实数字：DeepSeek v2 把原本 $N\times H=16384$ 维的 KV 压缩到只有 $C=512$ 维（因为 RoPE 位置编码和这种压缩方式有冲突，需要额外保留 64 维专门做 RoPE，实际共 576 维），压缩了超过 25 倍，而论文报告的准确率甚至略优于标准多头注意力，同时开销小得多。
  • 局部（滑窗）注意力：每一层只关注附近的局部上下文，KV Cache 大小和序列长度完全无关；但纯局部注意力会损害对长距离信息的建模能力，实践中通常和全局注意力层交替使用（混合层架构）。

三、 量化、推测采样与 PagedAttention：在不同层面上继续压缩和加速

既然生成阶段的瓶颈是"显存带宽"，另一条直接的优化路径是降低数值精度，精度越低，搬运同样数量的参数需要传输的字节就越少。讲义列出真实的精度谱系：训练常用 bf16（2 字节），更激进的推理量化可以用 int8（1 字节）甚至 int4（0.5 字节）。量化的关键权衡在于精度损失：训练后量化（PTQ）成本低但可能损失精度；量化感知训练（QAT）在训练过程中就模拟量化误差，精度更好但需要额外的训练开销；AWQ 这类方法则观察到"只有一小部分（0.1%-1%）权重对精度特别关键"，有针对性地保留这部分权重的高精度，其余大胆量化，据称能在 fp16→int3 的压缩下拿到 4 倍显存节省、3.2 倍速度提升。

推测采样（Speculative Sampling）是一个特别巧妙、值得多讲几句的技巧：既然生成阶段"检查一个候选 token 是否合理"（可以并行做，算力密集）比"真的生成它"（必须串行，显存密集）要快得多，那不如先用一个便宜的小"草稿模型"快速猜出接下来几个 token，再让真正的大模型一次性并行检查这几个候选、接受合理的、拒绝不合理的。讲义给出了一个简洁的数学论证，说明这个过程严格等价于直接从大模型采样（不是近似）：假设草稿模型对某个 token 的采样概率是 $p$、目标模型是 $q$，如果 $p(A) > q(A)$（草稿模型对 A 过采样），则通过"以 $q(A)/p(A)$ 的概率接受草稿模型采出的 A、否则从残差分布 $\max(q-p,0)$ 里重新采样"这一整套修正后的拒绝采样规则，最终采到每个 token 的概率恰好精确等于 $q$。这意味着推测采样不是"牺牲一点精度换速度"，而是数学上严格无损的加速。真实部署里常见的搭配是 70B 大模型配 8B 草稿模型，或者用 Medusa、EAGLE 这类方法让草稿过程本身也利用大模型的中间特征，进一步提高猜中率。

最后，真实的线上服务还要处理"动态工作负载"，不同请求到达时间不同、长度不同，训练时那种"规整的 batch_size × seq_len 张量"假设完全不成立。连续批处理（Continuous Batching，源自 Orca 系统）不再等一整批请求都处理完才开始下一批，而是按"生成步骤"为粒度动态调度，新请求随时可以插入正在进行的 batch。PagedAttention（vLLM 提出）则借用了操作系统里"分页"的经典思想：不再为每个请求预先分配一整块连续显存（容易产生"内部碎片"，预留的空间用不完；和"外部碎片"，空闲空间零散分布拼不成一块），而是把 KV Cache 切成非连续的固定大小"块"，按需分配，不同请求之间还能共享相同的系统提示词前缀，大幅提高显存利用率。这也是 vLLM 至今仍是最常用的开源推理框架之一的核心原因。

四、 评估：不存在唯一正确的"好模型"标准，选错评估方式会误导整个研究方向

这一讲后半段转向一个经常被低估的话题：怎么定义"这个模型好不好"。讲义指出，评估表面上是机械流程（设计 prompt、拿到回复、算准确率），但真正的难点在于，你要评估的往往是一个抽象、模糊的构念（比如"智能""有用性"），却必须把它落实成一个具体、可计算的指标，这个"抽象构念 → 具体指标"的转译过程本身充满取舍，不同的转译方式会得出完全不同、甚至互相矛盾的排名结论（跑分榜排名靠前的模型，未必是"人类更喜欢用"的模型，也未必是"更便宜好用"的模型）。

困惑度（Perplexity）是最早、也至今仍在广泛使用的评估指标，它衡量模型给真实数据分配的概率有多高。讲义提出了一个很值得记住的哲学立场，可以概括成"困惑度信仰"：如果模型的分布 $p$ 真的等于真实语言的分布 $t$，那么理论上模型就能解决一切任务（因为"解题"不过是对 $p(\text{解答}\mid\text{问题})$ 采样），持续压低困惑度，理论上终将通向更强的智能。但讲义也马上给出了反例："斯坦福成立于 1885 年"这句话里，困惑度会均匀地惩罚每一个 token 的预测误差，但"成立于"这几个字对我们真正关心的事实（1885 这个年份）而言并不重要。这提示困惑度有时"管得太宽"，衡量的和我们真正关心的能力之间存在错位。

于是评估的实践逐渐从困惑度走向更具体的能力型基准测试，讲义特别拿 MMLU（Massive Multitask Language Understanding）举例：57 个学科的多选题，从数学、美国历史到法律、伦理，由研究生和本科生从公开资料整理而成。它的名字虽然叫"语言理解"，但讲义直言：MMLU 测的其实主要是知识储备，而不是真正的语言理解能力，随着模型越来越强，MMLU 的区分度也逐渐饱和，于是又有了 MMLU-Pro：把选项从 4 个扩到 10 个、删掉过于简单或有噪声的题目、要求用思维链作答，结果模型准确率普遍下降 16 到 33 个百分点，重新拉开了区分度。这条"基准饱和 → 设计更难的新基准"的演进循环，本身就是这门课反复强调的一个更大主题：任何单一评估指标都有生命周期，理解它衡量的到底是什么、局限在哪里，比死记它的数字更重要。
