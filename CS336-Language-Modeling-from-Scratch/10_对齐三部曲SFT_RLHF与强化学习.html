第十讲：对齐三部曲——SFT、RLHF 与强化学习

从"预测下一个词"到"把正确答案的概率调高"，完整推导 GRPO 算法的每一步

主讲：Percy Liang / Tatsunori Hashimoto（斯坦福大学计算机系）
对应真实课程材料：Assignment 5（Alignment）Section 2-4

一、 一个根本性的目标转变：从"模仿数据"到"最大化奖励"

前九讲讨论的预训练，目标始终是交叉熵损失 $E_{x\sim\mathcal{D}}[-\log \pi_\theta(x)]$——从一个固定数据集里采样，让模型去模仿数据集里已经写好的文本。这一讲要讨论的对齐阶段，目标变成了完全不同性质的东西：

$$J_\theta = E_{x\sim\rho}\, E_{y\sim\pi_\theta(y\mid x)}[\,r(y \mid x)\,]$$

这里 $x$ 是问题（比如一道数学题），$y$ 是模型自己生成的回答，$r(y\mid x)$ 是一个打分函数（在可验证的任务里，比如数学题，通常就是"答案对不对"，对为 1、错为 0）。关键的区别在于：训练信号不再来自一个固定的数据集，而来自模型自己采样出的回答——这正是需要引入强化学习（RL）的根本原因，也是这一讲要完整推导的对象：组相对策略优化（Group Relative Policy Optimization, GRPO），这是 DeepSeek-R1 等推理模型训练中使用的核心算法之一。

在正式进入 GRPO 之前，作业先花了一定篇幅讨论"提示工程"（zero-shot、few-shot、思维链提示）——这是因为一个反复被验证的现象：用思维链提示对一个足够强的基座模型做强化学习，能带来推理能力的显著提升（OpenAI 的 o1 系列、DeepSeek-R1 的技术报告都指出了这一点）。也就是说，RL 训练的起点（用什么提示格式采样）和 RL 本身的算法设计，是两个同样重要、必须一起考虑的因素。

二、 把语言模型看成一个"策略"：强化学习的记号如何对应到生成文字

要理解 GRPO，先要把语言模型的生成过程，翻译成强化学习的标准语言。在强化学习里，"策略"（policy）根据当前"状态"（state）选择一个"动作"（action），进而获得"奖励"（reward）。对语言模型而言，这个对应关系是：当前已经生成的文本前缀就是状态 $s_t$，模型即将生成的下一个 token 就是动作 $a_t$，模型本身就是一个"策略"：

$$a_t \sim \pi_\theta(\cdot \mid s_t), \qquad \pi_\theta(a_t \mid s_t) = \big[\text{softmax}(f_\theta(s_t))\big]_{a_t}$$

从初始状态（一个采样出的问题 $x$）开始，逐个生成 token，直到遇到结束符，这整个过程叫一条"轨迹"（trajectory，也叫 episode 或 rollout）。在数学题这类"可验证"的任务上，中间生成过程不产生任何奖励，只有在生成完整回答后，才根据答案是否正确给出唯一的终局奖励 $r_T \in \{0, 1\}$——这和前几讲讨论的、每个 token 都有明确交叉熵损失反馈的预训练完全不同：强化学习里的反馈是稀疏的、延迟的、只在最后才揭晓。

三、 从最朴素的 REINFORCE，一步步推导到 GRPO

目标函数 $J_\theta$ 涉及对模型自己采样出的样本求期望，没法直接对参数求梯度求解析解，必须想办法把梯度重新写成一个可以从采样中估计出来的表达式。这一步用到一个经典技巧——对数导数技巧（log-derivative trick，源自 $\nabla \log f(x) = f'(x)/f(x)$）：

$$\nabla_\theta \pi_\theta(y\mid x) = \pi_\theta(y\mid x)\,\nabla_\theta \log \pi_\theta(y\mid x)$$

代入目标函数的梯度，可以推出（这正是以 REINFORCE 算法命名的经典结果）：

$$\nabla_\theta J_\theta = E_{y\sim\pi_\theta(y\mid x)}\big[\,r(y\mid x)\,\nabla_\theta \log \pi_\theta(y\mid x)\,\big]$$

这个式子翻译成一句话就是整个策略梯度方法的直觉核心：把每个采样出来的回答，按它获得的奖励加权，去调整"生成这个回答的对数概率"——奖励越高的回答，它出现的概率就被调得越高。写成可以直接在一个 batch 上计算的采样估计量：给定 $B$ 个问题，每个问题采样 $G$ 个回答，

$$\hat{g} \leftarrow \frac{1}{BG}\sum_{i=1}^{B}\sum_{j=1}^{G} r(y^{(i,j)}\mid x^{(i)})\, \nabla_\theta \log \pi_\theta(y^{(i,j)}\mid x^{(i)})$$

这就是最基础的策略梯度估计量——GRPO 正是在这个起点上，逐步叠加了四层改进。

改进一：减去一个基线（Baseline），降低方差

最基础的 REINFORCE 估计量方向无偏，但方差很大，训练很不稳定。一个经典技巧是给奖励减去一个和当前回答 $y$ 无关的基线值 $b$：只要 $b$ 不依赖于 $y$，这个操作完全不改变梯度的期望值（因为 $E_{y}[\nabla_\theta \log \pi_\theta(y\mid x)] = \nabla_\theta E_y[1] = 0$），但可以显著降低方差。举个直观例子：如果 $b=0.5$、奖励是 0/1 二值，原本"答对了升权重 1、答错了不做任何事"的更新，变成了"答对了升权重 0.5、答错了降权重 0.5"——错误答案第一次真正获得了明确的负反馈信号，而不只是"没有奖励"。

改进二：用"组内平均奖励"作为基线——这正是 GRPO 名字里"组相对"的由来

GRPO 选择的基线不是任意常数，而是同一个问题、同一组采样出的 $G$ 个回答的平均奖励 $\mu_i = \frac{1}{G}\sum_j r(y^{(i,j)}\mid x^{(i)})$：

$$\hat{g} \leftarrow \frac{1}{BG}\sum_{i=1}^{B}\sum_{j=1}^{G} \big(r(y^{(i,j)}\mid x^{(i)}) - \mu_i\big)\, \nabla_\theta \log \pi_\theta(y^{(i,j)}\mid x^{(i)})$$

减去组内平均之后的量，被称为"优势"（advantage）——衡量的不再是"这个回答绝对意义上好不好"，而是"这个回答相对于模型自己在同一道题上采样出的其他回答，是更好还是更差"。这个设计有一个很直接的现实好处：完全不需要额外训练一个独立的价值函数/评论家网络（critic）来估计基线（这正是 GRPO 相比传统 PPO 更省显存、更简单的核心原因）——只需要对同一个问题多采样几次，用组内的相对表现自己给自己打分。

改进三：除以组内标准差，让每组的更新幅度大致相当

在减去均值的基础上，GRPO 进一步除以组内奖励的标准差 $\text{std}_i$。这一步不再严格保持梯度期望不变（意味着 GRPO 优化的已经不完全是原始的期望奖励目标），可以理解为一种稳定性技巧：如果假设每组的梯度近似服从高斯分布，除以标准差能让每一组梯度更新的量级大致相当，避免某些"组内奖励方差特别大"的问题主导整体更新。

改进四：按序列长度归一化

对数似然 $\log \pi_\theta(y\mid x)$ 本身是对回答里每个 token 对数概率的求和——这意味着不加处理的话，越长的回答天然获得越大的梯度信号。GRPO 额外除以回答长度 $\text{len}(y^{(i,j)})$ 做归一化，让长回答和短回答里每个 token 受到的权重大致相当，而不是"长回答自动获得更大话语权"。

把以上几步组合起来，就是标准的在线（on-policy）GRPO 算法：每一步采样一批问题、每个问题采样 $G$ 个回答、计算组内归一化后的优势，再据此更新参数。作业还提到了一个更进阶的场景——离线（off-policy）GRPO：如果想在同一批采样数据上多走几步梯度更新（而不是每采样一次只更新一次，以提高训练效率），第二步开始所用的样本就已经是"过时"的（来自更早版本的模型），这时需要引入"裁剪重要性加权"（clipped importance reweighting）来修正这种分布偏移——这也是 PPO 类算法里"裁剪"操作的来源，防止单次更新的步子迈得过大导致训练崩溃。

四、 SFT 和 RLHF：GRPO 之外，对齐流程里的另外两块拼图

GRPO 这类强化学习方法，通常不是从一个刚预训练完、什么指令都不会听的模型直接开始训练的。真实的对齐流程一般是三步走：先做监督微调（SFT）——用一批人工或模型生成的高质量"问题-回答"范例，让模型先学会基本的指令遵循格式和回答风格；再视任务而定，用基于人类反馈的强化学习（RLHF）或本讲重点推导的可验证奖励强化学习（如 GRPO 用在数学题这类有明确对错的任务上）进一步提升模型能力。RLHF 和 GRPO 最大的区别在于奖励信号的来源：RLHF 的奖励来自一个额外训练出的"奖励模型"（拟合人类偏好排序得到），而 GRPO 用在可验证任务上时，奖励可以是一个确定性的规则化函数（比如直接检查数学答案是否正确），不需要额外训练奖励模型、也不存在奖励模型本身被"骗过"的风险——这也是为什么 DeepSeek-R1 等推理模型的技术报告特别强调"可验证奖励"这条路径的价值：比起依赖一个可能存在偏差、可能被"刷分"的学习出来的奖励模型，直接用客观可验证的规则作为奖励，训练信号更干净、更不容易被模型钻空子。

这一讲，连同前面九讲，构成了 CS336"从零构建"这条主线完整的技术拼图：从字节到 token，从矩阵乘法到完整的 Transformer 架构，从单卡的算子融合到跨机房的分布式训练，从算力预算到具体的模型配置，从推理系统的显存优化到数据工程的完整流水线，最终落到这一讲——让一个已经具备通识知识的预训练模型，通过强化学习学会把它的能力真正用在解决具体问题上。
