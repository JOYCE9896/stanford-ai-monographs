第四讲：混合专家模型 MoE 的路由与负载均衡

从注意力机制的替代方案，到"同样算力、更多参数"的稀疏专家网络设计全景

主讲：Tatsunori Hashimoto（斯坦福大学计算机系助理教授）
对应真实课程材料：Lecture 4 讲稿/幻灯片（Attention Alternatives and Mixtures of Experts）

一、 开场铺垫：为什么要先讲注意力的替代方案

这一讲开头并不是直接讲 MoE，而是先讨论了一个相关但独立的问题：标准自注意力的计算量随上下文长度呈平方增长（$O(n^2)$），当上下文窗口越拉越长，这个成本会变得无法忽视。讲义梳理了一条真实的技术演进路线：从"线性注意力"（把 $QK^\top V$ 通过结合律重排成 $Q(K^\top V)$，把复杂度从 $n^2 d_k + n^2 d_v$ 降到 $2nd_vd_k$）开始，线性注意力还有一个巧妙的性质：它可以写成和循环神经网络（RNN）等价的递推形式 $S_t = S_{t-1} + k_t v_t^\top,\ y_t = q_t^\top S_t$，训练时用并行的矩阵形式（快），推理时用串行的递推形式（省显存），这种"双重形式"的设计思路后续被 Mamba-2、Gated DeltaNet 等架构反复借鉴和扩展，并已经出现在 MiniMax M1、Qwen3.5（Qwen-Next）、Nemotron 3 等真实发布的模型里，通常做法是把少数几层换成线性/状态空间层、其余保留标准注意力的"混合架构"。这条线索和 MoE 有一个共同的出发点：标准 Transformer 里"每个 token 都要激活全部参数/全部计算"这件事，本身就有很大的压缩和稀疏化空间。这也是理解 MoE 设计动机的一个更大背景。

二、 MoE 是什么：用一个"选择器"决定每个 token 该交给哪个前馈网络处理

标准 Transformer block 里，每个 token 都会流过同一个前馈网络（FFN）。混合专家模型（Mixture of Experts, MoE）的做法是：把这一个 FFN 换成多个结构相同的 FFN（称为"专家"，expert），再加一个"路由"（router / gating）模块，为每个 token 决定应该交给哪几个专家处理，而不是让所有专家都处理所有 token。

这个设计最关键的性质是：增加专家的总数，并不会增加处理每个 token 所需的计算量（FLOPs），因为每个 token 依然只会被路由给其中少数几个专家，其余专家对这个 token 而言完全"闲置"。这意味着模型的总参数量可以远大于它处理单个 token 时实际激活的参数量，这正是讲义里反复强调的 MoE 流行起来的原因："同样的 FLOPs 预算下，参数更多的模型效果更好"，而且实践中 MoE 往往比同等激活参数量的稠密（dense）模型训练更快，也更容易做设备间并行（因为不同专家天然可以放在不同的 GPU 上）。

讲义给出了一张非常直观的真实模型对比表，列出了近几年主流 MoE 模型"路由专家总数 / 每次激活专家数 / 常驻共享专家数"的具体配置：

模型路由专家总数每次激活数共享专家数
GShard204820
Switch Transformer6410
Mixtral820
DBRX1640
DeepSeek v16462
Qwen 1.56044
DeepSeek v325681
Llama 4 (Maverick)12811

可以看到一个清晰的演进趋势：早期模型（如 Switch Transformer、Mixtral）专家数量较少、每个专家相对"大"；越晚近的模型（如 DeepSeek v3）越倾向于用更多、更细粒度（更小）的专家，同时保留一到两个"共享专家"（shared expert）。这些共享专家对每一个 token 都始终激活，不参与路由竞争，用来承担一些所有 token 都需要的通用计算，让其余"路由专家"可以更专注于学习差异化的、稀疏激活的知识。

三、 路由算法：几乎所有主流方案都是"Top-K"

如何决定一个 token 该交给哪几个专家？讲义指出，尽管学术界尝试过强化学习选路由、专家反过来"挑选"token、全局最优匹配等多种思路，但实践中几乎所有主流 MoE 都用同一种最朴素的方法：给每个专家算一个打分（通常是一个逻辑回归/线性层输出后过 softmax），取分数最高的 Top-K 个专家。不同模型只是在 $K$ 的取值上有区别：Switch Transformer 取 $K=1$（每个 token 只交给一个专家，最激进的稀疏化），GShard/Grok/Mixtral 取 $K=2$，Qwen 和 DBRX 取 $K=4$，DeepSeek 取 $K=6$ 到 $8$。

Top-K 路由带来一个根本性的工程难题："选择第几名"这个离散决策是不可微的，没法直接用梯度下降训练路由器该怎么选。讲义总结了三条业界尝试过的解法，用强化学习优化路由策略（理论上"最正确"，但梯度方差太大、复杂度太高，实践中很少真正采用）；给路由打分加随机扰动，让训练更稳健（Shazeer 2017 用高斯扰动、Fedus 2022 用均匀乘性扰动，但后者在 Zoph 2022 中又被移除）；以及目前实际用得最多的方案，用一个启发式的"负载均衡损失"（load balancing loss）作为辅助训练目标，直接惩罚"专家使用不均衡"这件事。

Switch Transformer 论文给出的负载均衡损失有一个很直观的性质：对专家 $i$ 被选中概率 $p_i(x)$ 的梯度是

$$\frac{\partial \mathcal{L}_{\text{balance}}}{\partial p_i(x)} \propto \frac{\alpha N}{T^2}\sum \mathbb{1}[\arg\max p(x) = i]$$

翻译成人话：一个专家被选中得越频繁，这个惩罚项对它的"降权"力度就越强。这是一种自我纠偏的机制，逼着路由器把负载摊匀，而不是让少数几个专家把大部分 token 都吃掉、其余专家训练不充分。DeepSeek v1-v2 用的是这个思路的变体，同时对"每个专家"和"每台设备上的专家总负载"分别加均衡约束（后者是因为真实训练是多机多卡的，设备间负载不均会直接拖慢整体训练速度）。DeepSeek v3 则更进一步，提出了"无辅助损失的负载均衡"（auxiliary-loss-free balancing），给每个专家维护一个可以在线调整的偏置项，用来动态提高或压低它被选中的倾向，从而在不引入额外损失函数、不干扰主训练目标的前提下实现负载均衡（讲义也坦诚指出，这个方法并不是完全不用任何辅助机制，只是把"辅助损失"换成了"辅助偏置"）。

四、 训练 MoE 的稳定性陷阱：不是搭好架构就能直接训

讲义列出了几个 MoE 特有、稠密模型不会遇到的训练稳定性问题，这些是理解"为什么 MoE 直到最近几年才真正大规模流行"的关键：

  • Token 丢弃（Token Dropping）：路由决策是在一个 batch 内部完成的，如果某个专家在这个 batch 里被分配到的 token 数量超过了它的容量上限，多出来的 token 就会被直接丢弃、不做任何处理。这意味着同一个请求会不会被"完整处理"，可能取决于同一批次里恰好还有哪些其他人的请求在排队。这是 MoE 模型一个反直觉的额外随机性来源。
  • 路由器数值不稳定：解法是给专家路由器单独用 float32 精度计算（即便模型主体用半精度），有时还会额外加一个"z-loss"来约束路由 logits 的数值范围，防止训练发散。
  • 小数据微调容易过拟合：稀疏 MoE 在小规模微调数据上比稠密模型更容易过拟合。不同团队给出了不同解法，Zoph et al. 选择只微调非 MoE 的部分（即冻结专家层）；DeepSeek 的解法更直接：用规模大得多的监督微调数据（140 万条）来稀释过拟合风险。

还有一条被称为"upcycling"（升级重塑）的实用路径：不从零训练 MoE，而是用一个已经训练好的稠密模型去初始化 MoE 的各个专家（比如把同一个前馈网络复制成多份作为初始专家权重），再继续训练。讲义提到的 MiniCPM（8 专家、Top-2，约 40 亿激活参数）和 Qwen MoE（从 Qwen-1.8B 初始化，60 专家 + 4 共享专家、Top-4）都是这条路径下的真实案例，好处是能省掉从零训练一个大 MoE 所需的巨量算力。

这一讲最后用 DeepSeek 从 v1 到 v3 的架构演进做了收尾，把上面几条线索串在了一起：v1（总参数 160 亿、激活 28 亿）是标准 Top-K 路由加专家/设备两级均衡损失；v2（总参数 2360 亿、激活 210 亿）把专家切得更细（160 个路由专家中选 6 个），并引入了跨设备的通信均衡损失；v3（总参数 6710 亿、激活 370 亿）走向"无辅助损失均衡" + 序列级均衡损失的组合，并且还搭配了两项配套创新，多头潜在注意力（MLA，把 Query/Key/Value 都表示成一个低维"潜在"向量的函数，从而让推理时需要缓存的 KV 显存大幅缩小）和多 token 预测（MTP，用小模型辅助预测未来不止一步的 token，这个思路会在后面推理系统那一讲里再展开）。
