第二讲：PyTorch 资源核算与显存精算

在写一行训练代码之前，先学会用纸笔算清楚"这个模型能不能塞进我的显卡"

主讲：Percy Liang（斯坦福大学计算机系教授）
对应真实课程材料：Lecture 2 讲稿、Assignment 1（Basics）Section 3.2、Section 4

一、 背景知识：为什么"算力核算"要单独用一讲来教？

初学者写深度学习代码时，最常见的挫败体验是这样的：模型定义得好好的，一跑训练就报 CUDA out of memory，然后开始盲目地把 batch_size 从 32 改成 16、再改成 8，试到不报错为止。CS336 明确反对这种"试错式"工作方式，它要求学生在写代码之前，先能用纸笔把一个 Transformer 训练一步需要多少次浮点运算（FLOPs）、需要多少字节显存，精确算出来。这不是学究式的形式主义：在真实的大模型训练中，一次失败的显存溢出可能意味着浪费几个小时甚至几天的 GPU 时间，提前算清楚"能不能跑"比事后调试省钱得多。

这一讲要建立的核心技能，课程原话叫"FLOPs accounting"（算力核算），一套可以套用在任何模型架构上的通用方法。

二、 背景知识：FLOPs 到底在数什么？

FLOP（floating point operation）就是一次浮点运算，比如一次乘法或一次加法。为什么要用它当计量单位，而不是"参数量"？因为同样参数量的模型，处理不同长度的输入所需要的实际计算量是不一样的，参数量衡量的是"模型有多大"，FLOPs 衡量的才是"这一次前向传播实际要算多少下"。

Transformer 里绝大多数计算都是矩阵乘法，所以整个核算方法可以浓缩成一条规则：给定矩阵 $A \in \mathbb{R}^{m \times n}$ 和 $B \in \mathbb{R}^{n \times p}$，矩阵乘法 $AB$ 需要的浮点运算次数是

$$\text{FLOPs}(AB) = 2mnp$$

这个"2"从哪来？结果矩阵的每一个元素 $(AB)[i,j]$ 都是一次长度为 $n$ 的点积，$n$ 次乘法加 $n$ 次加法，一共 $2n$ 次运算；结果矩阵一共有 $m \times p$ 个元素，所以总量是 $(2n)(mp) = 2mnp$。只要把 Transformer 前向传播中所有的矩阵乘法一条条列出来，套这条公式加总，就能得到一次前向传播的总 FLOPs。这正是本讲和 Assignment 1 里 "transformer_accounting" 那道题要求学生亲手做一遍的事。

作业给出了一个非常具体、可以直接照着算一遍的例子：一个 GPT-2 XL 规模的模型，配置是 vocab_size=50,257、context_length=1,024、num_layers=48、d_model=1,600、num_heads=25、d_ff=4,288（$\frac{8}{3} \times 1600$ 取最近的 64 的倍数）。把这套配置代入公式，会发现随着模型变大，QKV 投影和输出投影这些"参数矩阵"贡献的 FLOPs 占比会持续上升，而自注意力本身（$QK^\top$ 和加权求和）占比会相对下降，直到把 context_length 从 1,024 拉长到 16,384，注意力这部分因为和序列长度呈平方关系（$O(n^2)$），占比又会迅速反超回来。这个"模型变大 vs. 序列变长，谁在算力上更贵"的直觉，会在后面讨论 Scaling Laws 和推理系统时反复用到。

三、 背景知识：训练一步，显存里到底装了什么？

"模型能不能塞进显卡"这个问题，答案不是"参数占多少显存"这么简单。作业把训练时的显存占用拆成四块，缺一不可：

  • 参数（Parameters）：模型权重本身，float32 下每个参数占 4 字节。
  • 梯度（Gradients）：反向传播算出来的、和参数形状完全相同的梯度张量，同样是每参数 4 字节，相当于要再存一份和参数一样大的东西。
  • 优化器状态（Optimizer State）：这是最容易被初学者忽略的一块。AdamW 是"有状态"的优化器，它为每一个参数额外维护两个滑动平均量（一阶矩 $m$ 和二阶矩 $v$），也就是说每个参数背后还要再背两份和自己形状相同的浮点数。仅优化器状态这一项，就相当于再吃掉 2 倍参数量的显存。
  • 激活值（Activations）：前向传播过程中间层的输出（RMSNorm 的输出、$QK^\top$ 的结果、SwiGLU 里各个分支的中间值……），反向传播要用到它们来算梯度，所以训练时必须把它们暂存在显存里，而且这一项会随 batch_size 线性增长。

把这四项加起来，会得到一个形如 $a \cdot \text{batch\_size} + b$ 的表达式，$b$ 是和 batch size 无关的"固定开销"（参数、梯度、优化器状态），$a$ 是每增加一条样本就要多付出的"激活值成本"。这正是作业要求学生对 GPT-2 XL 配置具体算出来的：给定一张 80GB 显存的 GPU（对应真实的 A100/H100 训练卡型号），代入这个表达式反解，就能得到"最多能开多大的 batch size"这个所有调参工程师每天都要面对的真实数字。这也是为什么"轻量降级"（作业里称为 Low-Resource Tip）会建议先在小模型、小 batch 上跑通逻辑，再逐步放大，你永远应该先用这套核算方法在纸面上确认可行，而不是直接跑起来等着崩溃。

四、 从 SGD 到 AdamW：优化器是如何在 PyTorch 里"接线"的

这一讲的第二个核心内容，是让学生亲手实现一个 torch.optim.Optimizer 的子类。这也是理解"模型是怎么学会东西的"最直接的方式。最朴素的优化器是随机梯度下降（SGD）：

$$\theta_{t+1} \leftarrow \theta_t - \alpha_t \nabla L(\theta_t; B_t)$$

换成人话：每一步，都朝着"让损失下降最快"的方向（梯度的反方向），迈出一步，步子大小由学习率 $\alpha$ 控制。作业给出的最小可运行示例，把 PyTorch 优化器 API 的两个必需方法讲得很清楚：__init__ 里要把参数集合和超参数传给父类构造函数；step() 里遍历每一个参数，读取它的梯度 p.grad，原地更新 p.data。一个可以直接跑的玩具训练循环长这样： 

weights = torch.nn.Parameter(5 * torch.randn((10, 10)))
opt = SGD([weights], lr=1)
for t in range(100):
    opt.zero_grad()          # 清空上一步残留的梯度
    loss = (weights**2).mean())
    loss.backward()          # 反向传播，算出梯度
    opt.step()                # 优化器按梯度更新参数

但真实的大模型几乎不会直接用 SGD，而是用 AdamW，它在 Adam 的基础上，把权重衰减（weight decay，每一步都把参数轻轻拉向 0，防止过拟合）从梯度更新中解耦出来，独立处理。AdamW 有三组关键超参数：学习率 $\alpha$、控制一阶/二阶矩滑动平均速度的 $(\beta_1, \beta_2)$，以及权重衰减系数 $\lambda$。一个很实用的真实经验数字：通用场景常用 $(\beta_1,\beta_2)=(0.9, 0.999)$，但 LLaMA、GPT-3 这类大语言模型的训练配置里，$\beta_2$ 往往被调低到 0.95。这不是随意选择，而是大规模训练中的经验教训：$\beta_2$ 太接近 1，二阶矩估计对最近梯度的变化会反应迟钝，在动辄训练数周的大模型任务上，这种迟钝可能积累成训练不稳定。

交叉熵损失（训练时优化的目标）和困惑度（评估时报告的指标）之间的关系也值得记一下：给定模型对每个位置输出的 logits，交叉熵损失是

$$\ell(\theta; D) = \frac{1}{|D|\, m}\sum_{x \in D}\sum_{i=1}^{m} -\log p_\theta(x_{i+1} \mid x_{1:i})$$

而困惑度就是把平均交叉熵取指数：$\text{perplexity} = \exp\left(\frac{1}{m}\sum_i \ell_i\right)$。直观理解：困惑度可以看成"模型平均要在多少个候选词里才能蒙对下一个词"，数值越接近 1，说明模型对下一个词越确定；数值越大，说明模型越"困惑"。
