第八讲：原生多模态智能与统一表征

给图像单独接一个"翻译器"和让模型从一开始就同时读图像和文字，是两种不同的设计

主讲：Victoria Lin（Thinking Machines Lab，前 Meta Superintelligence Labs）
对应真实研究：Chameleon（早期融合多模态基础模型）、MoMa（模态感知混合专家架构）、LMFusion（NeurIPS 2025）

一、 背景知识：两种做多模态模型的方式

让一个模型同时处理文字和图像，有两种常见思路。第一种叫"后期融合"：分别训练一个文本模型和一个图像编码器，再用一个额外的适配层，把图像编码器输出的特征"翻译"成文本模型能理解的格式接进去。这种做法的好处是可以复用已经训练好的单模态模型，工程上更省事，但两种模态从一开始就是在各自独立的表示空间里训练的，适配层能做的只是事后对齐，天然存在信息损耗。

第二种是"早期融合"（early fusion），也就是这一讲标题里"原生多模态"的含义：从预训练最开始，就把图像和文字放进同一套 token 序列、用同一个模型统一训练，模型从头学习的就是一个能同时容纳两种模态的表示空间，而不是先分别学两套表示、再想办法接起来。Victoria Lin 的研究主要围绕后一种思路展开。

二、 Chameleon：把图像也变成 token

Chameleon 是 Lin 参与开发的一个早期融合基础模型，核心做法是用一个图像分词器（image tokenizer）把图像切分转换成离散的 token 序列，和文本 token 用完全相同的方式对待。这样模型看到的输入，不再是"一段文字加一张图片"这种两种不同数据类型的拼接，而是一整条统一的 token 序列，图文可以在序列里任意交错出现，模型用同一套 Transformer 架构、同一个训练目标（预测下一个 token）来处理这整条序列。

这个设计的直接好处是生成侧的灵活性：模型可以在一段回复里自由穿插文字和图像，而不需要一个专门的"图像生成分支"和一个专门的"文本生成分支"分别工作再拼接结果。代价是图像分词本身会造成信息损耗，把连续的像素信息压缩成有限的离散 token，不可避免会丢失一些细节，这也是这类早期融合模型持续在优化的一个方向。

三、 MoMa：不同模态的信息值得用不同的专家处理吗

MoMa 在早期融合的基础上引入了混合专家（Mixture-of-Experts）结构，但做了一个模态感知的改动：路由器在挑选专家子网络时，会考虑当前 token 来自哪种模态。这个设计背后的判断是，文字 token 和图像 token 承载信息的统计特性并不相同，用完全相同的一组专家不加区分地处理两者，可能不是最优的参数分配方式。

通过让不同模态的信息更多地路由到各自更擅长的专家子网络，MoMa 想要在保留统一表示空间这个早期融合的核心优势的同时，让模型的参数使用效率更接近针对每种模态单独优化的水平。这类工作反映出原生多模态模型这条路线目前的一个核心张力：统一处理带来更好的跨模态融合，但完全不区分模态又可能牺牲一部分针对性。

四、 LMFusion：让已有的语言模型学会生成图像

LMFusion（发表于 NeurIPS 2025）探讨了一个更实际的问题：现在已经有大量训练成本高昂、能力很强的纯文本语言模型，能不能在不从头重新预训练的前提下，给它们新增多模态生成能力？做法是在保留原有文本模型权重和能力的基础上，引入额外的模块专门处理图像相关的生成任务，让模型在原有语言能力不退化的情况下获得新的模态处理能力。

这类工作的现实意义在于成本。从零训练一个原生多模态大模型需要极高的算力投入，如果能在已有的、已经投入巨大成本训练好的语言模型基础上增量扩展出多模态能力，会大幅降低多模态化的门槛。这一讲把这几项工作放在一起看，反映出"原生多模态"这个方向目前正在两个目标之间寻找平衡：一端是从头设计、统一程度最高的架构，另一端是尽量复用已有投入、增量扩展模态能力的工程路径。
