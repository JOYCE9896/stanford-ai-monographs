第二讲：测试期算力扩展定律、Pass@k 指数幂律与验证瓶颈之壁

反复采样的数学本质、覆盖率对数线性方程与多数投票在规模化下的虚假共识陷阱

核心文献：Large Language Monkeys (Brown et al., 2024) · Snell et al. (2024) · Archon Framework
主讲教授：Aakanksha Chowdhery & Azalia Mirhoseini · 深入解构 Test-Time Compute

一、 核心范式跃迁：从预训练缩放转向测试期算力弹性

在 2024 年之前，AI 学界的主流信仰被 Kaplan 与 Chinchilla 的经典预训练缩放法则所统治：要想让模型表现提升，唯一的途径是在集群中堆砌更多的浮点预算，训练更大参数量 N 的模型与摄入更多的数据量 D。

什么是测试期算力与 Pass@k？

普通人使用 ChatGPT 时习惯了"你问一句、它立刻答一句"，但这隐藏着一个反常识的缺陷：问 AI"法国首都是哪"，它用 0.2 秒回答；问 AI"帮我证明一道奥数几何题"，它同样被迫在 0.2 秒内吐字，这等于逼着一个天才不打草稿、张口就要答对极其复杂的代数难题。

测试期算力（Test-Time Compute）允许模型多花一点时间和电费：面对一道高难度编程题，让模型在后台生成 k 个独立解答（比如 k = 100），只要这 100 个解答里有至少 1 个在测试沙盒里完全跑通（Pass@100），就算通关。斯坦福实测表明，一个体量仅为 8B 的中型小模型，给它 250 次独立解题机会并自动跑测试筛选，在复杂软件工程基准 SWE-bench 上的解题成功率直接碾压了万亿参数但只许做一次的 GPT-4。这就是为什么 OpenAI o1/o3 和 Claude 深度思考模式都把重心转移到了"思考时间"。

在斯坦福 CS329A 的第二讲中，导师彻底揭示了旧范式的盲区：预训练算力是在编译期一次性固化的静态资产，而真实世界的问题难度在推理期呈现出极端的非均匀长尾分布。传统的贪婪解码对任何问题均施加完全相同的单次前向浮点开销，无论是询问"法国的首都是哪里"，还是要求"证明黎曼猜想在特定临界线上的收敛性"，模型都被迫在几百毫秒内吐出第一个 Token，这种机制违背了人类思考的基本认知规律。

由此，测试期计算缩放应运而生。其核心思想是：将算力消耗的主战场从耗资数亿美元的前期预训练，转移到用户面对具体复杂任务时的动态即时推理。

二、 核心数学模型：Pass@k 与覆盖率指数幂律

在由 Bradley Brown、Jordan Juravsky 与 Azalia Mirhoseini 合作发表的里程碑论文《Large Language Monkeys: Scaling Inference Compute with Repeated Sampling》中，研究者严格形式化了反复采样在拓宽模型解题边界上的数学表现。

1. Pass@k 的无偏估计公式

在对特定复杂问题生成 n 个独立候选解答（n ≥ k），且其中有 c 个解答被环境判决器确认为正确时，传统的评测方式会引发极大的方差。论文采用下述无偏估计量来计算系统在允许 k 次尝试时的期望成功概率： 

pass@k = E_problems [ 1 - (C(n - c, k) / C(n, k)) ]
where:
  • n: 实际采样的候选总数（如 n = 10,000）
  • c: 经验证完全正确的候选样本数
  • C(N, K): 组合数计算公式 N! / (K! * (N - K)!)

2. 覆盖率跨越 4 个数量级的惊人幂律

当采样预算 k 从 1 激增至 10,000 时，解决问题的覆盖率（Coverage，即 k 次采样中至少有一次命中正确答案的概率）并未如传统悲观预期那样迅速饱和，而是遵循一条广义指数化幂律：

$$\text{Coverage}(k) = 1 - \exp\left(-\alpha \cdot k^\beta\right)$$

在 GSM8K、MATH（高中数学竞赛）、CodeContests（算法竞赛）及 SWE-bench 上，拟合系数 β ∈ [0.4, 0.7]，显示出跨越四个计算数量级（100 ~ 104）的高度普适性与外推能力。

这一物理规律揭示了一个底层真相：只要基座模型的非零概率分布空间中包含了通往正确逻辑的微弱路径，通过海量采样就必然能够以数学上的确定性将其从高维隐空间中"轰击"出来。

三、 核心实证震撼：SWE-bench 上的反直觉颠覆

8B 模型反复采样全面击穿万亿闭源巨头

在真实世界的软件工程基准 SWE-bench Lite（要求 Agent 解决 GitHub 真实仓库中的复杂 Bug）中，论文记录了一场性能翻盘：GPT-4 单次贪婪前向传播的基准通过率仅为 43.0%，曾被视为不可逾越的天花板；DeepSeek-Coder-V2-Instruct 单次采样（pass@1）仅为 15.9%；而同一模型在 250 次独立采样（pass@250）下，通过率暴涨至 56.0%。

一个开源的、体量适中的中型代码模型，在搭配了 250 次推理采样预算后，在解题广度上直接碾碎了参数大它数十倍的单一顶尖基座模型。这意味着：在具备自动化测试用例的环境中，堆砌测试期算力的边际收益远远大于等待新一代预训练基座模型的发布。

四、 致命的阿喀琉斯之踵：验证瓶颈

然而，斯坦福 CS329A 绝不停留在盲目乐观的技术狂欢中。Azalia Mirhoseini 教授在黑板上画出了这门课程最震撼的一张对比曲线图，覆盖率（Coverage）与选择准确率（Selection Accuracy）的巨大剪刀差。

为什么采样越多，多数投票反而死得越惨？

工业界常用的自洽性策略（Self-Consistency / Majority Voting）假设：正确的答案往往是唯一的，而错误的答案会以随机噪声的形式分散在概率空间各处，因此只要统计出现频次最高的答案，就能筛出真理。这一假设在困难逻辑与复杂编码问题上被实证彻底粉碎。

实验表明：当采样次数 k 超过某个阈值（通常在 k > 100 ~ 250）后，多数投票的准确率不仅不再上升，反而开始急剧掉头向下溃败。

底层致病机理在于：大语言模型是由人类数据训练出来的，它们共享着相同的人类认知偏见与注意力捷径。在面对极其困难的逻辑陷阱时，模型并不会随机犯错，而是会集体陷入极具共性的"系统性幻觉陷阱"。例如在复杂的数学代数变形中，80% 的采样样本会不约而同地漏掉同一个隐式正负号边界条件，并异口同声地给出一个看似完美但完全错误的假答案；而唯一推导正确的路径，由于逻辑步步惊心，其生成概率极低，在 10,000 次采样中可能仅出现 3 次。

结论：在此类场景下盲目扩增采样，只会让错误的假答案以压倒性的"假民主多数票"将极少数真理彻底淹没。

这就是著名的验证瓶颈（Verification Bottleneck）：如果一个领域缺乏类似编译器或单元测试那样的确定性判决标准，单纯依靠反复采样增加测试期算力，不仅无法提升性能，反而会因为验证能力的缺失而彻底退化为高功耗的算力自嗨。Charlie Snell 等人（2024）在《Scaling LLM Test-Time Compute Optimally》中量化了这一拐点：在缺乏高质量奖励模型监督时，继续追加推理 FLOPs 的边际效用在 N > 64 后趋近于零。

正因如此，如何构建脱离人类投票偏见、能够对每一步逻辑推理进行严格审查的过程级鲁棒验证器（Process-Supervised Verifiers），成为了自演进 AI 系统的生死分水岭，这正是第三讲所要攻克的终极要塞。
